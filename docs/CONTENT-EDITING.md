# Content Editing Guide

Content is validated at build time. A malformed field, duplicate route, or broken internal link fails `npm run validate` before it can reach production.

## Where content lives

| Collection | Location | Format | Primary fields |
|---|---|---|---|
| Services | `src/content/services/` | YAML | `title`, `slug`, `order`, `summary`, `thesis`, six `workstreams`, `metrics`, `relatedPaths`; optional `heroMedia`, `supportingMedia` |
| People | `src/content/people/` | Markdown | `name`, `role`, `tier`, `order`, `image`, `alt`; biography in the body |
| Clients/projects | `src/content/clients/` | Markdown | `name`, `slug`, `route`, `category`, `tier`, `logo`, `legacyUrl`; profile in the body |
| Posts | `src/content/posts/` | Markdown | `title`, `slug`, `route`, dates, `author`, `categories`, `featuredMedia`, `draft`; article body and optional structured `contentBlocks` |
| Additional pages | `src/content/legacy-pages/` | Markdown | `title`, `slug`, `route`, `description`, `originalUrl`, `updatedDate`; page copy in the body |
| Primary page content | `src/content/site-pages/` | YAML | Metadata and approved editable sections for the homepage, services index, and contact page |

Category and author route identifiers are migration-managed; names and descriptions are editable in Tina. The four mockup-led services and nine team profiles are maintained manually; WordPress-derived clients, posts, and legacy pages were initially generated by the migration script. They are now editor-managed; do not rerun the importer over editorial changes.

Tina covers the public content collections and shared labels. Agents edit the same files through Git; team editors use `/admin/` and can publish directly. Marketing records are in `src/content/marketing/`; navigation/footer/default CTA records are in `src/content/settings/`. See `docs/TINA-EDITOR.md` for coverage, creation, Markdown-body editing and deployment setup.

## Service example

```yaml
title: Example Service
slug: example-service
order: 5
eyebrow: What We Do
summary: A concise approved summary.
thesisLabel: Why This Matters
thesis: Approved narrative copy.
workstreams:
  - title: First workstream
    description: What this workstream covers.
# Exactly six workstreams are required.
metrics:
  - value: 5–10%
    label: A sourced, approved result range
# At least three metrics are required.
metricsNote: State the scope and source limitation.
relatedPaths:
  - /approach/
# Optional. Omit media fields for the approved text-led layout.
heroMedia:
  src: /wp-content/uploads/2026/08/example.jpg
  alt: A factual description of what is visible in the image.
  width: 1600
  height: 1067
  position: center
supportingMedia:
  src: /wp-content/uploads/2026/08/example-detail.jpg
  alt: A factual description of the supporting image.
  width: 1600
  height: 1067
```

## Post example

```markdown
---
title: Example Post
slug: example-post
route: /example-post/
excerpt: A factual summary drawn from the article.
publishedDate: 2026-08-25T09:00:00
updatedDate: 2026-08-25T09:00:00
author: author-slug
categories:
  - category-slug
featuredMedia: /wp-content/uploads/2026/08/example.jpg
canonicalUrl: https://storesconsulting.com/example-post/
draft: true
sourceId: 99999
---

Article copy starts here.
```

## Images and links

- New approved assets go in `public/assets/` with descriptive lowercase filenames.
- Images uploaded through Tina go in `public/assets/editorial/`.
- Migrated WordPress assets stay at their original `/wp-content/uploads/...` path.
- Service media is optional. Omit `heroMedia` or `supportingMedia` when no relevant approved image exists; never use a placeholder or repeated generic stock.
- Every structured image requires factual alt text and intrinsic dimensions. Use `position` only to control an otherwise unsuitable crop.
- Use root-relative internal links such as `/approach/`.
- Include the trailing slash on page routes.
- Do not use inline scripts, event handlers, layout HTML, or fake `#` links.

## Validation and review

```bash
npm ci
npm run validate
```

Use `npm run tina:audit` after changing Tina schemas or editor-managed content. TinaCloud credentials are not required for local validation.

For structural changes, also run `npm run test:e2e`; for editable fields or preview wiring, run `npm run test:editing`. Run these commands sequentially. See [the developer guide](DEVELOPMENT.md) for the architecture and extension recipes. Review the Vercel preview at 320, 390, 768, 1024, and 1440 pixels before approval.
